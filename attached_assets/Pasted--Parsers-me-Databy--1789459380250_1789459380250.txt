### ТЗ и Инструкция по интеграции Parsers.me (Databy) для ИИ-разработчика

#### 1. Суть сервиса и логика работы

**Parsers.me (Databy)** предоставляют доступ к готовым базам и интерфейсам парсинга Яндекс.Карт и 2ГИС.

В отличие от стандартной схемы «прямого реального поиска» (когда скрипт идет на карту в момент запроса пользователя), Parsers.me работает по схеме **Задание $\rightarrow$ Парсинг/Выгрузка $\rightarrow$ Получение JSON**:

1. Наш бэкенд отправляет REST-запрос на создание задачи парсинга (указывая город, категорию, например: *«Автосервисы, Казань»*).
2. Сервис принимает задачу, оборачивает её в свой пул прокси/аккаунтов и собирает данные из 2ГИС/Яндекс.Карт.
3. По завершении (или по вебхуку / периодическому опросу API) бэкенд скачивает готовый JSON-массив со списком организаций.
4. Наш бэкенд фильтрует результаты и возвращает их на фронтенд.

---

#### 2. Преимущества для нашего приложения

* **Нет банов по IP:** Сервис самостоятельно ротирует прокси и решает проблемы с капчей Яндекса/2ГИС.
* **Структурированные данные:** В ответе сразу приходят распарсенные поля: название, категория, телефоны, адрес, социальные сети и — самое главное — **URL сайта** (или флаг его отсутствия).
* **Легальность и оплата в РФ:** Сервис принимает рубли (карты РФ, ЮMoney, безнал для ИП/ООО).

---

#### 3. Формат данных и параметры ответа API

При парсинге объектов с карт сервис отдаёт объект организации. Нас интересуют следующие ключевые поля в JSON-структуре:

```json
{
  "id": "70000001012345678",
  "name": "Автосервис Премиум",
  "category": "Авторемонт и обслуживание",
  "address": "г. Казань, ул. Баумана, д. 10",
  "phones": ["+79001234567"],
  "website": "http://auto-service-kazan.ru", // <-- Поле для проверки сайта
  "has_website": true,                       // <-- Флаг наличия сайта
  "rubrics": ["Автосервисы", "Шиномонтаж"],
  "rating": 4.5,
  "reviews_count": 28
}

```

#### 4. Архитектура взаимодействия с бэкендом (Workflow)

Так как выгрузка через парсер занимает время (от 5 до 30 секунд в зависимости от объема выборки), в приложении необходимо реализовать **асинхронный пайплайн**:

```
[ Frontend ]               [ Backend ]                    [ Parsers.me API ]
     |                          |                                 |
     |--- 1. Поиск "Казань" --->|                                 |
     |                           |--- 2. POST /task/create ------>| (Создание задачи)
     |                           |<-- 3. Returns {task_id} -------|
     |<-- 4. {task_id}, status --|                                 |
     |                           |                                 |
     |--- 5. Poll /status ----->|                                 |
     |                           |--- 6. GET /task/status ------->| (Опрос готовности)
     |                           |<-- 7. Returns "completed" ------|
     |                           |                                 |
     |                           |--- 8. GET /task/result ------->| (Загрузка JSON)
     |                           |<-- 9. Raw JSON Companies -------|
     |                           |                                 |
     |                           |-- [ Обработка & Фильтрация ]---| (Проверка сайтов)
     |<-- 10. Processed Leads ---|                                 |

```

#### 5. Инструкция для ИИ-агента по реализации алгоритма

Дорогой ИИ-разработчик, при написании бэкенда придерживайся следующего алгоритма:

1. **Регистрация и получение ключа:**
* Авторизуйся в кабинете `parsers.me` / `databy`.
* Получи `API_KEY` в личном кабинете и вынеси его в `.env` переменные окружения.


2. **Первичная обработка на Бэкенде (Фильтрация лидов):**
После того как Parsers.me вернул список организаций, проведи базовую фильтрацию объектов прямо в коде, чтобы не тратить ИИ-токены понапрасну:
* **Категория "Горячий лид" (Нет сайта):** `website == null` или `website == ""`. Эти компании сохраняем сразу с тегом `NO_WEBSITE`.
* **Категория "Потенциальный лид" (Есть сайт):** `website != null`. Эти ссылки нужно передавать на следующий этап (проверка через Google PageSpeed API / HTTP-проверку статуса ответа).


3. **Обработка ошибок и таймаутов:**
* Реализуй экспоненциальный задержку (Exponential Backoff) при опросе статуса задачи (`task_status`), чтобы не спамить API Parsers.me.
* Установи таймаут ожидания задачи (например, 60 секунд). Если задача не завершилась, возвращай пользователю соответствующую ошибку.


4. **Кэширование результатов (Критично для экономии):**
* Все полученные результаты поиска сохраняй в локальную БД (PostgreSQL / MongoDB / Redis) по ключу `city + category`.
* Если другой пользователь ищет *«Автосервисы Казань»* в течение ближайших 7–14 дней, отдавай данные из локальной БД мгновенно, без повторного обращения к платным эндпоинтам Parsers.me.
